# RabConverter v1

## Tujuan

User mengunggah PDF RAB dan mendapatkan file Excel yang bisa diedit serta memiliki rumus. Fokus utama adalah **akurasi hasil**, dengan pengalaman yang sesederhana mungkin.

## Alur produk

1. **Upload PDF.** Satu area upload menerima PDF melalui pilih file atau drag-and-drop.
2. **Preflight otomatis.** Validasi PDF, hitung halaman, cek saldo kuota, dan tunjukkan estimasi harga maksimum yang relevan.
3. **Kuota cukup:** konversi langsung dimulai. **Kuota tidak cukup:** jangan panggil provider; tampilkan saldo, estimasi kebutuhan, dan langkah top-up.
4. **Konversi.** Ekstrak baris RAB dan susun workbook Excel, termasuk rumus yang benar-benar didukung oleh data sumber.
5. **Cek hasil.** Pastikan file XLSX terbentuk, baris/angka penting tidak hilang atau berganda, dan perhitungan yang bisa diperiksa cocok dengan angka tercetak.
6. **Berhasil.** Potong kuota satu kali berdasarkan halaman RAB substantif yang berhasil dipertahankan di workbook. Tampilkan **Download Excel**.
7. **Gagal.** Tampilkan pesan yang dapat dimengerti. Jangan potong kuota jika file Excel yang layak diunduh tidak berhasil dibuat.

Harga awal: **Rp2.500 per halaman tertagih**. Minimum top-up yang direncanakan: **Rp50.000**. Tarif harus terlihat sebelum upload. Sebelum mulai proses, pemeriksaan saldo memakai jumlah halaman PDF sebagai estimasi maksimum; tagihan akhir menghitung halaman berisi data RAB substantif yang berhasil dipertahankan di Excel.

## Stack yang dipilih untuk v1

Stack ini sengaja dibuat kecil. Komponen tambahan tidak dimasukkan sampai alur inti bekerja.

| Bagian | Pilihan v1 | Tugas |
|---|---|---|
| UI | React + TypeScript + Vite | Satu halaman upload, status proses, dan download |
| Hosting UI | Cloudflare Pages | Menyajikan aplikasi web |
| Login | Supabase Auth | Mengenali user dan mengambil kuotanya |
| Data kuota | Supabase PostgreSQL | Menyimpan saldo dan memotong kuota secara atomik setelah konversi berhasil |
| Endpoint konversi | Satu Supabase Edge Function: convert-rab | Cek kuota, panggil provider, bentuk XLSX, cek hasil, debit kuota, kirim file |
| Ekstraksi | Reducto Extract; Deep Extract untuk benchmark awal | Mengambil tabel dan data RAB dengan struktur/citation bila tersedia |
| File Excel | SheetJS Community Edition (paket npm xlsx) | Menulis file XLSX dan formula |
| Repo/CI | GitHub dan pemeriksaan build/test dasar | Simpan kode dan pastikan aplikasi bisa dibangun |

Referensi teknis:
- [Supabase Edge Functions](https://supabase.com/docs/guides/functions) — endpoint TypeScript untuk mengintegrasikan provider dan Supabase.
- [Reducto Extract](https://reducto.ai/extract) — ekstraksi dokumen ke JSON terstruktur dan dukungan citation.
- [SheetJS: formula](https://docs.sheetjs.com/docs/csf/features/formulae/) — formula dapat ditulis ke XLSX; SheetJS tidak menghitung rumus secara otomatis. RabConverter harus menghitung hasil aritmetika yang didukung, menulis formula dan nilai hasilnya, lalu membandingkan dengan angka sumber.
- [Cloudflare Pages](https://developers.cloudflare.com/pages/) — hosting frontend.

### Batas teknis yang perlu diuji pertama kali

Satu Supabase Edge Function cukup untuk percobaan awal, tetapi runtime hosted punya batas CPU/memori dan durasi. Uji empat PDF sintetis untuk memastikan ekstraksi dan pembuatan XLSX berjalan dalam batasnya. Jangan tambahkan queue atau server baru sejak awal. Jika benchmark nyata membuktikan batas runtime tidak cukup, pindahkan hanya proses konversinya ke runtime yang sesuai tanpa mengubah pengalaman pengguna.

### Yang sengaja tidak dibuat di v1

- Tidak ada queue/Redis atau orkestrasi multi-job.
- Tidak ada beberapa provider dan fallback AI.
- Tidak ada penyimpanan permanen semua PDF/hasil atau riwayat konversi.
- Tidak ada dashboard analitik, editor tabel interaktif, atau wizard banyak langkah.
- Integrasi pembayaran otomatis belum dipilih; validasi konversi dapat memakai kuota uji yang diisi untuk testing sebelum payment gateway dibuat.

## Inspirasi UX dari remove.bg

remove.bg dikenal dengan alur otomatis: user memilih gambar, sistem menghapus background, dan hasilnya siap diunduh tanpa pengguna harus mengatur pemisahan manual. Untuk referensi, lihat [penjelasan resmi remove.bg](https://www.remove.bg/id/help/a/what-is-remove-bg/).

RabConverter mengambil **prinsip interaksi** tersebut, bukan menyalin visual, logo, warna merek, atau teknologi remove.bg.

### Layar utama

- Header sederhana dengan nama RabConverter.
- Judul jelas: **Ubah PDF RAB ke Excel**.
- Penjelasan pendek tentang harga per halaman dan bahwa output berisi rumus hasil rekonstruksi.
- Area upload besar dengan tombol **Pilih PDF RAB** dan dukungan drag-and-drop.
- Hindari kartu fitur, menu dashboard, metrik, dan penjelasan teknis yang mengganggu aksi utama.

### Setelah upload

- Tampilkan nama file, jumlah halaman, saldo kuota, dan estimasi biaya.
- Kuota cukup → mulai konversi otomatis, tanpa tombol atau halaman tambahan.
- Kuota kurang → hentikan sebelum provider dipanggil dan tampilkan ajakan top-up.
- Saat proses berjalan, tampilkan status yang jujur, misalnya “Membaca tabel RAB”, “Menyusun Excel”, atau “Memeriksa hasil”. Jangan membuat persentase palsu.

### Hasil

- Pesan sederhana **Excel siap diunduh**.
- Satu tombol utama **Download Excel**.
- Tampilkan jumlah halaman tertagih dan warning akurasi hanya bila ada.
- Saat gagal, jelaskan penyebab yang diketahui. Jangan potong kuota.

Tampilan harus bersih, responsif di ponsel, dan berpusat pada satu aksi. Tidak ada keharusan meninjau atau mengedit seluruh tabel untuk kasus normal.

## Prinsip akurasi

- Ambil hanya data yang didukung sumber: kode dan uraian pekerjaan, satuan, volume, harga satuan, jumlah tercetak, subtotal, total, dan kelompok pekerjaan.
- PDF biasanya tidak menyimpan formula Excel aslinya. Formula output adalah formula hasil rekonstruksi.
- Buat formula hanya jika hubungan datanya jelas. Jangan menebak harga, volume, atau nilai yang tidak terbaca.
- Bandingkan nilai hitung dengan jumlah, subtotal, dan total tercetak. Jika berbeda, jangan menyembunyikan selisih.
- File yang tidak lolos pemeriksaan dasar tidak boleh dianggap berhasil dan tidak menimbulkan pemotongan kuota.

## Kriteria selesai v1

Satu PDF sintetis dapat diproses end-to-end: upload → cek kuota → ekstraksi → XLSX dengan formula → pemeriksaan dasar → pemotongan kuota satu kali → download. Jika gagal, saldo kuota tetap. Keempat fixture harus diuji sebelum melanjutkan ke dokumen pelanggan.
