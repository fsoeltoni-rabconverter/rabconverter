# Decision Log

Record decisions that affect product behavior, data contracts and infrastructure.

## DEC-001: Formula-bearing Excel from PDF RAB is the MVP

- Status: Proposed
- Date: 2026-10-25
- Context: The product's primary user goal is to stop retyping a provided PDF RAB into Excel, with working formulas in the exported workbook.
- Decision: Focus MVP on PDF RAB/BOQ table extraction, review, safe formula reconstruction, source-vs-calculated reconciliation and XLSX download.
- Constraint: A PDF typically does not retain the original Excel formula graph. Formulas generated by RabConverter must be labelled reconstructed and must not be described as exact recovery.
- Consequence: Exact original workbook fidelity, drawing-based quantity takeoff, generic market pricing and portal submission remain out of scope.
- Evidence: product-definition.md, contractor-workflow.md, research-and-sources.md.

## DEC-002: Use remove.bg as interaction simplicity reference only

- Status: Proposed
- Date: 2026-10-25
- Decision: Adopt the focused upload → processing → review/download flow, not visual assets or exact branding.
- Consequence: Make conversion the central loop; defer complex dashboards.

## DEC-003: Cloud-only development workflow

- Status: Proposed
- Date: 2026-10-25
- Decision: GitHub is source of truth, GitHub Actions runs checks/deploys, Cloudflare hosts preview/app, Supabase provides data/auth/storage as needed.
- Consequence: No required local workflow; previews must be reviewable before production deployment.

## DEC-004: Reconstructed formulas must be traceable

- Status: Proposed
- Date: 2026-10-25
- Context: PDF exposes printed values but not usually spreadsheet formula references.
- Decision: Preserve each printed amount separately from reconstructed formula/result, label provenance and flag mismatches instead of silently overriding source values.
- Consequence: Formula reconstruction and reconciliation are release-blocking acceptance tests.
